## 作ったもの

[ex-langgraph](https://github.com/iinow/ex-langgraph) は [Eino](https://github.com/cloudwego/eino) で作ったエージェントのサンプルです。Gin サーバーに質問を送ると SSE で答えが流れ、会話とツール呼び出しの記録は MySQL に残ってウェブ画面から見られます。モデルは OpenAI 互換のアドレスなら何でもつながり、既定はローカルの Ollama の `qwen2.5:3b` です。

<ol class="loop" aria-label="エージェントの反復順序">
  <li>質問</li>
  <li>model</li>
  <li class="hot">ツール呼び出し?</li>
  <li class="hot">tools</li>
  <li>model</li>
  <li>回答</li>
</ol>

ノードは `model` と `tools` の 2 つだけです。モデルの応答にツール呼び出しがあれば `tools` へ、なければ終わりへ進みます。モデルがツールばかり呼び続けるのを防ぐため、ノードの実行は 10 回で打ち切ります。

## 迷ったところ: ノードは直前の出力しか受け取らない

グラフでは、ノード同士はすぐ前のノードの出力だけをやり取りします。`tools` ノードはツールの結果しか渡さないので、そのままだとモデルは元の質問を見られません。そこでグラフの state に会話全体を積んでおき、`model` ノードに入る直前に丸ごと差し替えます。

```go
compose.WithStatePreHandler(func(ctx context.Context, in []*schema.Message, s *state) ([]*schema.Message, error) {
    s.history = append(s.history, in...) // 入ってきたもの(質問かツール結果)を積み、
    return s.history, nil                // モデルには会話全体を渡す
})
```

state は実行 1 回のあいだだけ生きます。長く残す記録は、メッセージができるたびにフックで DB へ直接書きます。途中で失敗しても、そこまでの会話は残ります。

## 答えが流れてくる形

Eino のコールバックでトークンとツール呼び出しを受け取り、そのまま SSE イベントとして出します。

| イベント | 意味 |
|---|---|
| `session` | セッション確定 (新しい会話なら新しい番号) |
| `tool_call` | ツール呼び出しの開始、名前と引数 |
| `tool_result` | ツール実行の結果 |
| `delta` | 回答トークンの断片 |
| `done` | 終わり、回答全体 |
| `error` | 実行中の失敗 |

ブラウザが接続を切ると context がキャンセルされ、実行も止まります。

## 大きなツール 1 つの中に小さなワークフロー

「キム・ミンジュンに車を勧めて」のような仕事は、ユーザーの照会、車両一覧の取得、選択、保存まで何段階にもなります。会話エージェントには `recommend_vehicle` という大きなツールを 1 つだけ渡し、その中で 3 段階を回します。

| 段階 | すること | 誰が決めるか |
|---|---|---|
| 照会 | 小さなエージェントが読み取り専用ツールでユーザーと候補を取ってくる | モデル |
| 結論 | 照会した会話を渡して JSON で答えさせる。選べる id はスキーマの enum に縛る | 形式はコード |
| 検証・保存 | 候補にある id か、理由があるか、必須の照会をしたかを見る。違えばやり直し、それでも違えば最初の候補 | コード |

データをプロンプトに埋め込まず、モデル自身にツールで取らせたのが要点です。

## 3b のモデルに任せてみると

同じ仕事を 2 つの方式でユーザー 3 人に対して回しました。

| | データをプロンプトに入れる | ツールで照会 |
|---|---|---|
| プロフィール写真選び | 3 人とも適切 | 3 人とも適切 |
| 車のおすすめ | 3 人とも適切 | 車両一覧の取得をよく飛ばして選ぶ |
| かかった時間 | 2〜4 秒 | 9〜20 秒 |

ツール照会は「モデルが必要なものを自分で取ってくる」を見せるには良いのですが、小さなモデルは照会を抜かし、遅いです。そこでコードで支えました。

| 3b が実際にした失敗 | 支えた方法 |
|---|---|
| 複数のツールを順番に使えない | 大きなツール 1 つ + 内側のワークフロー |
| id をでっち上げる (`u-キム・ミンジュン`) | 名前でも探し、先頭の `u-` を外して探し直す |
| ない id でツールを呼ぶ | エラーと一緒に候補一覧を返す |
| 候補外の id を選ぶ、理由を抜かす | JSON スキーマの enum と required |
| 必ずやるべき照会を飛ばす | 抜けていたらやり直させる |
| 空の応答を送って次の呼び出しが 400 | 送り直すときに空メッセージを外す |
| 女性ユーザーに男性の写真 | 性別の絞り込みはモデルに任せずコードがやる |

学んだことは単純です。モデルが得意なのは選ぶことと話すことで、形式・検証・絞り込みはコードが握っていないと、小さなモデルでは回りません。
