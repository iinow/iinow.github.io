## 만든 것

[ex-langgraph](https://github.com/iinow/ex-langgraph) 는 [Eino](https://github.com/cloudwego/eino) 로 만든 에이전트 예제입니다. Gin 서버에 질문을 보내면 답이 SSE 로 흘러나오고, 대화와 도구 호출 기록은 MySQL 에 남아 웹 화면에서 볼 수 있습니다. 모델은 OpenAI 호환 주소면 무엇이든 붙고, 기본은 로컬 Ollama 의 `qwen2.5:3b` 입니다.

<ol class="loop" aria-label="에이전트 반복 순서">
  <li>질문</li>
  <li>model</li>
  <li class="hot">도구 호출?</li>
  <li class="hot">tools</li>
  <li>model</li>
  <li>답변</li>
</ol>

노드는 `model` 과 `tools` 둘뿐입니다. 모델 응답에 도구 호출이 있으면 `tools` 로, 없으면 끝으로 갑니다. 모델이 도구만 계속 부르는 일을 막으려고 노드 실행은 10번에서 끊습니다.

## 헷갈렸던 한 가지: 노드는 직전 출력만 받는다

그래프에서 노드끼리는 바로 앞 노드의 출력만 주고받습니다. `tools` 노드는 도구 결과만 넘기니까, 그대로 두면 모델은 원래 질문을 못 봅니다. 그래서 그래프 state 에 대화 전체를 쌓아 두고, `model` 노드에 들어가기 직전에 통째로 바꿔 넣습니다.

```go
compose.WithStatePreHandler(func(ctx context.Context, in []*schema.Message, s *state) ([]*schema.Message, error) {
    s.history = append(s.history, in...) // 들어온 것(질문 또는 도구 결과)을 쌓고
    return s.history, nil                // 모델에는 전체 대화를 넘긴다
})
```

state 는 실행 한 번 동안만 삽니다. 오래 남길 기록은 메시지가 생길 때마다 훅으로 DB 에 바로 씁니다. 중간에 실패해도 그때까지의 대화는 남습니다.

## 답이 흘러나오는 모양

Eino 콜백에서 토큰과 도구 호출을 받아 그대로 SSE 이벤트로 내보냅니다.

| 이벤트 | 뜻 |
|---|---|
| `session` | 세션 확정 (새 대화면 새 번호) |
| `tool_call` | 도구 호출 시작, 이름과 인자 |
| `tool_result` | 도구 실행 결과 |
| `delta` | 답변 토큰 조각 |
| `done` | 끝, 전체 답변 |
| `error` | 실행 중 실패 |

브라우저가 연결을 끊으면 context 가 취소되어 실행도 멈춥니다.

## 큰 도구 하나 안에 작은 워크플로

"김민준한테 차 추천해 줘" 같은 일은 사용자 조회, 차량 목록 조회, 고르기, 저장까지 여러 단계입니다. 대화 에이전트에는 `recommend_vehicle` 이라는 큰 도구 하나만 주고, 그 안에서 세 단계를 돌립니다.

| 단계 | 하는 일 | 누가 정하나 |
|---|---|---|
| 조회 | 작은 에이전트가 읽기 전용 도구로 사용자와 후보를 가져온다 | 모델 |
| 결론 | 조회한 대화를 넘기고 JSON 으로 답하게 한다. 고를 수 있는 id 는 스키마의 enum 으로 묶는다 | 형식은 코드 |
| 검증·저장 | 후보에 있는 id 인지, 이유가 있는지, 필수 조회를 했는지 본다. 틀리면 다시, 그래도 틀리면 첫 후보 | 코드 |

데이터를 프롬프트에 끼워 넣지 않고 모델이 도구로 직접 가져오게 한 것이 핵심입니다.

## 3b 모델에게 맡겨 보니

같은 일을 두 방식으로 사용자 3명에게 돌렸습니다.

| | 데이터를 프롬프트에 넣기 | 도구로 조회 |
|---|---|---|
| 프로필 사진 고르기 | 3명 모두 적절 | 3명 모두 적절 |
| 차량 추천 | 3명 모두 적절 | 차량 목록 조회를 자주 건너뛰고 고름 |
| 걸린 시간 | 2~4초 | 9~20초 |

도구 조회는 "모델이 필요한 걸 스스로 가져온다"를 보여 주기엔 좋지만, 작은 모델은 조회를 빼먹고 느립니다. 그래서 코드로 받쳤습니다.

| 3b 가 실제로 한 실수 | 받쳐 준 방법 |
|---|---|
| 도구 여러 개를 순서대로 못 쓴다 | 큰 도구 하나 + 안쪽 워크플로 |
| id 를 지어낸다 (`u-김민준`) | 이름으로도 찾고, 앞의 `u-` 를 떼고 다시 찾는다 |
| 없는 id 로 도구를 부른다 | 에러와 함께 후보 목록을 돌려준다 |
| 후보 밖 id 를 고르거나 이유를 빼먹는다 | JSON 스키마의 enum 과 required |
| 꼭 해야 할 조회를 건너뛴다 | 빠졌으면 다시 시킨다 |
| 빈 응답을 보내 다음 호출이 400 | 다시 보낼 때 빈 메시지를 뺀다 |
| 여성 사용자에게 남성 사진 | 성별 거르기는 모델에게 안 맡기고 코드가 한다 |

배운 건 단순합니다. 모델이 잘하는 건 고르기와 말하기이고, 형식·검증·거르기는 코드가 쥐고 있어야 작은 모델로도 굴러갑니다.
