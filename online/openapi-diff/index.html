3엔드포인트별 변경

스펙을 넣고 비교하기를 누르면 결과가 여기에 나옵니다.

판정 기준 — 클라이언트를 고치지 않으면 깨지는 변경을 Breaking으로 봅니다.

  • Breaking: 엔드포인트·응답 코드 삭제, 필수 파라미터 추가, 파라미터가 선택→필수로 바뀜, 요청·응답 스키마의 타입 변경, 요청 본문의 필수 필드 추가, 응답 필드 삭제, 요청 enum 값 삭제, 응답 enum 값 추가.
  • 안전한 변경: 새 엔드포인트·선택 파라미터·선택 필드 추가, 응답 필드 추가, 요청 enum 값 추가, 선택으로 풀린 파라미터, deprecated 표시.
  • $ref는 문서 안에서 풀어서 비교하고, 같은 이름의 파라미터는 in과 이름으로 짝을 맞춥니다. 미디어 타입은 application/json을 먼저 봅니다.
  • 스펙은 어디로도 전송되지 않습니다. 파일도 브라우저에서만 읽습니다.
